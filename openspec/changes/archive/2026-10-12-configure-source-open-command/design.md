## Context

動機は [proposal.md](proposal.md)、動作契約は [specs/search-panel/spec.md](specs/search-panel/spec.md) と [specs/application-settings/spec.md](specs/application-settings/spec.md) を参照。検索欄のEnterと下部ボタンは同じ `SearchView.openSource()` を呼ぶ。既存のフォルダ・ショートカット設定は設定画面から操作する。

## Goals / Non-Goals

**Goals:**
- 既存の2入口から同じ元ファイル起動処理を使い、設定画面で適用した変更を直ちに反映する。
- `$file` をシェルで展開せず、空白を含む元ファイルの絶対パスを1引数として安全に渡す。
- 設定・起動エラーを利用者に知らせる。

**Non-Goals:**
- 設定のために外部ファイルを編集させない。
- 任意のシェルスクリプトを実行する機能は設けない。
- 既存仕様にある⌘Eのキー割り当ては本変更に含めない。

## Decisions

### 設定画面とUserDefaultsを使う

設定画面にコマンド入力欄・現在値・適用ボタン・入力エラーを置く。`code $file` のように入力して適用すると、構文を検証してUserDefaultsに保存し、検索パネルへ直ちに反映する。空欄を適用すれば既定アプリに戻る。適用せず画面を閉じた編集は破棄する。既存のショートカット・フォルダ設定と同じ操作様式にする。

### コマンドは引数列として解析して起動する

空白区切りと単一・二重引用符による引数のグループ化だけを許可する。`$file` は引数全体としてちょうど1回必要で、引用符で囲んだ `"$file"` も同じ意味とする。展開後は元Markdownの標準化した絶対パス1個に置換する。パイプ、リダイレクト、セミコロン、コマンド置換、他の変数展開は不正な設定として扱う。シェルに文字列を渡す案はファイル名やコマンドの解釈が変わり得るため採用しない。通常の文字列引数はそのまま渡す。

`Process` へ実行ファイルのURLと引数配列を渡す。コマンド名が絶対パスならそのまま使用し、単純な名前なら実行環境のPATHとmacOSで一般的な `/usr/local/bin`・`/opt/homebrew/bin` を探索する。これによりターミナルで利用可能な `code` をメニューバーアプリから見つけやすくする。見つからなければ起動せず案内し、ユーザーは設定に絶対パスを指定できる。

### エラー時は原因を表示する

複数行、構文不正、`$file` 不在は設定画面の適用時に表示し、旧設定を維持する。実行ファイルが見つからない、またはプロセス開始に失敗した場合は元ファイルを開く操作に対応したエラーを検索パネルに表示する。既定アプリへ黙って切り替えない。

### 呼び出し側は選択エントリの元URLを渡す

`SearchView.openSource()` から独立した起動部品へ元URLと適用済みコマンドを渡し、Enterとボタンの現行接続を維持する。候補がない場合は何もしない。コマンド起動はユーザーが元ファイルを開く時だけ行い、ショートカットでのパネル表示や候補検索にI/Oを足さない。検索構文・順位、起動時・60分ごと・手動更新、ローカル画像への影響はない。

## Risks / Trade-offs

- [macOSアプリとターミナルでPATHが異なり `code` が見つからない] → 一般的なCLI配置先を探索し、絶対パスの指定方法と失敗時の案内を文書化する。VS CodeのCLIが未導入なら導入が必要と案内する。
- [引用符や空白を含むファイル名が引数に分裂する] → `$file` を文字列置換でなく引数単位で扱い、空白・引用符・日本語を含むパスのテストで確認する。
- [不正な設定が意図しないコマンドを起動する] → 対象外のシェル構文と複数行を拒否し、実行ファイルが見つからない場合も既定アプリへ暗黙に切り替えない。
- [コマンドの書式が分かりにくい] → 設定画面に `code $file` の入力例と空欄時の動作を示す。

## Migration Plan

既存ユーザーには起動コマンドの保存値がないため、現行の既定アプリで開く動作を維持する。設定画面で空欄を適用すれば既定動作へ戻る。以前の外部ファイル案は未完了の実装であり、読み込まない。実機未確認の項目は検証記録に残す。
