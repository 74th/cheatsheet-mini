## Context

動機は [proposal.md](proposal.md)、契約は [specs/markdown-preview/spec.md](specs/markdown-preview/spec.md) を参照。現在の経路は `Down.toHTML()` → `embedLocalImages` → `WKWebView.loadHTMLString`。Downの既定変換では生HTMLをコメントに置き換えるため、元文書の `img` が後段へ渡らない。

ローカルに取得済みのDownの `DownOptions.swift` とcmarkの `html.c` で、既定の生HTML除去とcustom block/inlineノードの出力を確認した。SVGのdata URL埋め込み自体は既存処理にあり、指定されたSVGファイルも存在する。現時点では新しい表示経路の実装・実機検証は行っていない。

## Goals / Non-Goals

**Goals:**
- 文書を変更せず、本文中のHTML画像を既存の画像埋め込み経路に渡す。
- 生HTMLとコードをMarkdownパーサーで区別し、許可した属性だけから表示タグを生成する。
- HTML生成をUIから呼ぶテスト可能な関数にまとめ、変換から埋め込みまでを一つの検証対象にする。

**Non-Goals:**
- 全HTMLの許可やHTMLページ用の汎用サニタイザーは作らない。
- SVG内の図形・色・背景は編集しない。原本を画像として表示する。
- 画像の索引登録、再帰スキャン、新規の外部依存は追加しない。

## Decisions

### Markdownの構文木で生HTML画像だけを扱う

Down/cmarkの構文木を利用し、HTML block/inlineノードの画像タグのみを検出する。許可した画像タグを再生成し、対応するcustom block/inlineノードとして出力する。その他のノードは既定のレンダリングを継続し、コードノードやHTMLコメント、script本文の文字列に含まれる `img` を画像として抽出しない。複数画像を含むHTMLノードも順序を保って扱う。

単純な全文正規表現による置換は、fenced codeやinline codeのタグも画像化し得るため採用しない。`.unsafe` で全HTMLを通す案は画像以外の挙動まで変わるため採用しない。customノードの内容には原文HTMLをそのまま入れず、アプリが再生成した画像タグだけを使用する。

### 属性を限定して再生成する

タグ名・属性名の大小文字と属性の順序に依存せず、引用符で囲まれた `src`、`alt`、`title`、`width` を扱う。`src` のHTML文字参照を復号してから既存の相対パス処理へ渡し、出力する文字列属性はHTMLエスケープする。イベント属性、`style`、`srcset` 等は引き継がない。不正なタグや重複した `src` は採用しない。

`width` は正の整数ピクセルまたは0より大きく100以下のパーセントに限定する。適合する値だけから幅の指定を生成し、`max-width: 100%; height: auto` を維持する。無効値は幅指定を省略する。未引用属性など今回の契約外の構文は対象外とする。

### ローカル画像の制約と埋め込みを共用する

再生成した画像タグにも `embedLocalImages` を適用し、PNG/JPG/JPEG/GIF/WebP/SVG、15,000,000バイト未満、元Markdownフォルダ配下の相対参照という既存制約を維持する。HTML画像についてはローカル相対参照を許可対象とし、絶対パス・親フォルダ・独自スキーム・外部URLを新たに許可しない。既存のMarkdown記法による外部画像処理は変更しない。読めない画像の処理が周辺本文の表示を妨げないようにする。

`file://` を直接読み込ませる案は、現在のHTML文字列読み込みの制約に再び依存するため採用しない。data URLへの埋め込みを継続する。

### 表示時だけ変換する

選択エントリのプレビュー生成だけで処理し、検索候補の採点や索引作成に画像解析を入れない。検索構文、順位、起動時・60分ごと・手動更新の条件、ショートカット呼び出し時にスキャンしない動作を維持する。プレビューに必要な画像I/Oとメモリ検索の速度を区別し、本変更で50ms目標を達成済みとは扱わない。

## Risks / Trade-offs

- [構文木の置換でブロック構造や複数画像の順序を崩す] → 単独タグ、文中タグ、複数タグ、前後のMarkdown、コード中のタグをHTML生成テストで確認する。
- [タグ・属性解析の誤認識] → 引用符内の記号、属性順序、単一引用符、HTML文字参照、不正タグ、コメントやscript中の疑似タグを含むテストを用意する。
- [HTML生成成功だけでは実際のSVG表示を証明できない] → 指定の回路図をWKWebViewで確認し、幅変更への追従も実機で確認する。未確認事項は明記する。
- [Down/cmarkのAPI依存] → 取得済み依存のAST APIを使い、既存バージョンでビルドと回帰テストを実行する。

## Migration Plan

設定・文書・インデックスの移行は不要。プレビュー経路とテスト、利用者向けの対応範囲を更新してビルドする。取り消す場合は旧HTML生成経路へ戻せばよく、元文書への変更は必要ない。
