# Markdown Index Specification

## Purpose

Markdownをレベル2見出し単位の検索エントリに分割し、メモリ内のインデックスを起動時・定期・手動で更新する。

## Requirements

### Requirement: レベル2見出しによる分割
アプリは `##` 見出しから次の `##` 見出し直前までを1エントリとして保持する SHALL。見出し行を本文に含め、最後のエントリはファイル末尾までとする。`#` は文書タイトルとして扱い、`###` 以下の見出しは独立した検索エントリにしない。

#### Scenario: 複数のセクション
- **WHEN** Markdownに `## AAA` とその本文、続いて `## BBB` とその本文がある
- **THEN** AAAとBBBの2エントリを生成し、それぞれ自分の見出し行と本文を保持する

#### Scenario: 下位見出しを含むセクション
- **WHEN** `## AAA` の本文に `### 詳細` が含まれる
- **THEN** 詳細はAAAの本文に残り、独立した検索エントリにはならない

### Requirement: エントリの情報
各エントリは識別子、拡張子を除いたファイル名、文書タイトル、レベル2見出し、セクションのMarkdown、元ファイルURLを保持する SHALL。

#### Scenario: 元文書との対応
- **WHEN** `sbx.md` の文書タイトルとレベル2見出しを解析する
- **THEN** エントリはファイル名 `sbx`、文書タイトル、見出し、セクション本文、元の `sbx.md` のURLと識別子を持つ

### Requirement: コードフェンスの除外
アプリはコードフェンス内の `#` や `##` を文書タイトルやセクション見出しとして認識しない SHALL。バッククォートとチルダのフェンスに対応する。

#### Scenario: バッククォート内の見出し風テキスト
- **WHEN** `## test` の本文のバッククォートフェンス内に `## not heading` がある
- **THEN** testの1エントリのみを生成し、フェンス内の行を本文として保持する

#### Scenario: チルダ内の見出し風テキスト
- **WHEN** チルダフェンス内に `## not heading` がある
- **THEN** その行を検索見出しとしてインデックス化しない

### Requirement: 起動時のメモリ内インデックス構築
アプリは起動時に設定済みフォルダをスキャンし、Markdownを解析してメモリ上にインデックスを構築する SHALL。検索インデックスの永続化やDBを必要としない。

#### Scenario: 設定済みフォルダで起動する
- **WHEN** 保存された検索対象フォルダを復元してアプリを起動する
- **THEN** フォルダ直下のMarkdownからインデックスを構築する

### Requirement: 60分ごとの定期更新
アプリは起動時の構築後、固定の60分間隔で指定フォルダ直下をスキャンしてインデックスを更新する SHALL。スリープ中のタイマー実行は保証しない。

#### Scenario: 次の定期更新を迎える
- **WHEN** 起動後にMarkdownを変更し、アプリが動作中に次の60分間隔の更新が実行される
- **THEN** 変更内容がインデックスと検索結果へ反映される

### Requirement: ファイル単位の差分更新
アプリは各Markdownの更新日時とサイズを記録し、通常の定期スキャン時に前回値と比較する SHALL。新規ファイルを解析して追加し、変更ファイルの既存エントリを再解析結果へ置換し、削除ファイルのエントリを除去し、変更のないファイルを再解析しない。

#### Scenario: ファイルを追加する
- **WHEN** 前回スキャン後に新しいMarkdownを追加して定期スキャンする
- **THEN** 新規ファイルのセクションがインデックスに追加される

#### Scenario: ファイルを変更する
- **WHEN** 更新日時またはサイズが変化したMarkdownを定期スキャンする
- **THEN** そのファイルの古いエントリが再解析したエントリで置換される

#### Scenario: ファイルを削除する
- **WHEN** 前回スキャンにあったMarkdownを削除して定期スキャンする
- **THEN** そのファイルに属するエントリがインデックスから除去される

#### Scenario: ファイルに変更がない
- **WHEN** 更新日時とサイズが前回と同じMarkdownを定期スキャンする
- **THEN** キャッシュしたエントリを再利用し、そのファイルを再解析しない

### Requirement: 手動更新
アプリはメニューバーから60分を待たずにインデックスを更新できるようにする SHALL。手動更新は変更内容を検索結果へ反映する。

#### Scenario: 今すぐ変更を反映する
- **WHEN** Markdownを変更した後、メニューバーから手動更新を実行する
- **THEN** 次の定期更新を待たず変更が検索結果に反映される

### Requirement: 検索パネル呼び出しで更新を行わない
アプリは設定済みショートカットまたはメニューによる検索パネル呼び出し時にスキャン、更新確認、再インデックスを行わない SHALL。既に構築したインデックスを使用する。ショートカットのみの変更・設定画面の表示も更新を誘発しない。フォルダ変更による再構築はこの制約と区別する。

#### Scenario: 未スキャンの変更がある状態で表示する
- **WHEN** Markdownを変更した後、定期・手動更新前に設定済みショートカットを押す
- **THEN** 更新チェックをせず検索パネルを表示し、変更内容は次の更新まで反映されない

#### Scenario: 呼び出しキーのみを変更する
- **WHEN** 設定画面を開いてショートカットのみを変更し、そのキーでパネルを呼び出す
- **THEN** 設定表示・キー変更・パネル呼び出しのいずれもスキャンを実行しない

#### Scenario: メニューから呼び出す
- **WHEN** メニューから検索パネルを開く
- **THEN** 既存インデックスで表示し、更新確認を行わない
