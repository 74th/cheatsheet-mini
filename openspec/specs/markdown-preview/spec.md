# Markdown Preview Specification

## Purpose

選択したセクションを読みやすいMarkdownとして表示し、コードとローカル画像を含めて即座に参照する。

## Requirements

### Requirement: Markdownのレンダリング
アプリは選択エントリのMarkdownをレンダリングして表示する SHALL。最低限、見出し、段落、箇条書き、コードブロック、inline code、リンク、テーブル、画像に対応する。

#### Scenario: 基本文法を表示する
- **WHEN** 選択セクションに見出し、段落、箇条書き、inline code、リンクがある
- **THEN** 各要素をMarkdownとして表示する

#### Scenario: テーブルを表示する
- **WHEN** 選択セクションにMarkdownテーブルがある
- **THEN** 表として参照できる形で表示する

### Requirement: コードブロックの可読性
アプリはコードブロックの可読性を重視して表示する SHALL。構文強調の採用は必須としない。

#### Scenario: コマンドを読む
- **WHEN** 選択セクションに複数行のコードブロックがある
- **THEN** 行構造を保ち、通常の本文と区別して読みやすく表示する

### Requirement: コードブロックのコピー
アプリはプレビュー中の各コードブロックに、そのコードをクリップボードへコピーするボタンを表示する SHALL。コピーする内容はコードブロックの文字列そのままとし、末尾の改行1つは含めない。ボタンはコピーのアイコンで常に表示し、横スクロールしても位置を保つ。

#### Scenario: コードブロックをコピーする
- **WHEN** コードブロック右上のコピーボタンを押す
- **THEN** そのコードブロックの全文をクリップボードへコピーし、ボタンを一時的にチェックのアイコンに変える

#### Scenario: コマンドを貼り付ける
- **WHEN** 1行のコマンドのコードブロックをコピーしてターミナルに貼り付ける
- **THEN** 末尾に改行を含まないため、貼り付けただけではコマンドが実行されない

### Requirement: 相対パスのローカル画像
アプリはMarkdown画像記法および本文中のHTMLの `img` タグで指定した相対パス画像を元Markdownファイルの位置を基準に解決し、プレビュー上で表示する SHALL。インデックスがサブディレクトリを探索しないことは、画像参照先にサブディレクトリを利用できないことを意味しない。HTML画像タグの `src` は単一引用符または二重引用符で囲まれた値に対応する。画像形式・サイズ・参照範囲は従来と同じ制約を適用し、現在の制約は `openspec/README.md` に記録する。画像を読み込めない場合も、周辺の本文は表示する。

#### Scenario: imagesフォルダの画像を表示する
- **WHEN** `sbx.md` が `![image](images/example.png)` を含み、その相対位置に表示可能な画像が存在する
- **THEN** `sbx.md` のあるフォルダを基準に画像を解決し、プレビューに表示する

#### Scenario: フォルダごとの相対位置
- **WHEN** 別のフォルダにあるMarkdownが同じ `images/example.png` という相対パスを持つ
- **THEN** それぞれの元Markdownの位置を基準に画像を解決する

#### Scenario: HTMLで指定したSVGを表示する
- **WHEN** `electronic_work.md` の本文に `<img src="./electronic_work/Pch-MOSFET-AS-Diode.svg" width="80%">` があり、参照先に表示可能なSVGが存在する
- **THEN** 元Markdownのあるフォルダを基準にSVGを解決し、回路図を表示する
- **AND** 元MarkdownやSVGを書き換える必要がない

#### Scenario: 単一引用符の画像タグを表示する
- **WHEN** 本文に `<img src='./images/example.png'>` があり、参照先に表示可能な画像が存在する
- **THEN** 二重引用符の場合と同じ基準で画像を表示する

#### Scenario: 画像が見つからない
- **WHEN** HTML画像タグの参照先が存在しない、読み取れない、または既存の形式・サイズ制限の対象外である
- **THEN** 該当画像は表示されなくても、前後の本文を参照でき、プレビュー全体の表示に失敗しない

### Requirement: HTML画像タグの幅指定
アプリは本文のHTML画像タグの `width` に指定された正の整数ピクセル値または0より大きく100以下のパーセント値を表示幅に反映する SHALL。例えば `width="80%"` はプレビュー本文領域の幅の80%として表示し、画像の縦横比を維持する。ピクセル指定も本文領域の幅を上限とする。幅指定がない、または値が無効な場合は既定の画像表示を使い、任意のCSSとして解釈しない。

#### Scenario: パーセント幅を反映する
- **WHEN** `width="80%"` を指定した画像を表示し、パネルの幅を変える
- **THEN** 画像幅は本文領域の80%に追従し、縦横比を維持する

#### Scenario: ピクセル幅を反映する
- **WHEN** `width="320"` を指定した画像を表示する
- **THEN** 本文領域が十分に広ければ320 CSSピクセル幅で表示し、本文領域が狭ければその幅以内に収める

#### Scenario: 無効な幅指定
- **WHEN** 幅が未指定、負数、0、100を超えるパーセント、またはCSSなど数値以外の値である
- **THEN** 既定の表示幅で画像を表示し、縦横比と本文領域の幅の上限を維持する

### Requirement: HTML画像対応の範囲
アプリはHTML画像対応を本文の画像タグと画像表示に必要な属性に限定する SHALL。コードブロックやinline code内の画像タグは文字列として表示する。追加対応によってイベント属性や任意の生HTMLの実行を有効にせず、親フォルダ・絶対パス等の既存のローカル参照制限も維持する。

#### Scenario: コード例として画像タグを表示する
- **WHEN** fenced code block、インデントによるコードブロック、またはinline codeに `<img src="./images/example.svg" width="80%">` がある
- **THEN** タグはコードとして表示され、そのコード中のタグから画像を読み込まない

#### Scenario: イベント属性を含む画像タグ
- **WHEN** 本文の画像タグに `onerror` や `onload` 等のイベント属性が含まれる
- **THEN** 対応する画像は表示できても、それらのイベント属性は実行されない

#### Scenario: 他の生HTMLを含む本文
- **WHEN** 本文に `script` や `iframe` 等の対象外の生HTMLが含まれる
- **THEN** HTML画像対応に伴って、それらが実行・表示されるようにはならない

#### Scenario: 対象範囲外の画像を参照する
- **WHEN** HTML画像タグが `../outside.svg` や絶対パスの画像を参照する
- **THEN** ローカル画像表示の対象範囲を拡張せず、周辺の本文は引き続き表示する
